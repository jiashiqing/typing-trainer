# 部署全流程（小白版）

> 面向第一次把系统放到云服务器的人。每一步都写清「做什么 / 为什么 / 怎么验证 / 报错看哪里」。
> 当前这套实例：腾讯云 Ubuntu，公网 `43.142.117.18`，对外端口 **8090**。

---

## 一、先认识四个部件

部署不是在服务器上"双击运行"。它由四样东西协作，少一样都跑不起来。

| 部件 | 打个比方 | 干什么 | 它出问题时的症状 |
|---|---|---|---|
| **Nginx** | 门卫 | 站在 8090 门口，先查网页口令，再决定放不放进来 | 404 / 401 / 500，浏览器直接打不开 |
| **Node.js** | 厨师 | 房子里的真实程序（`server.js`），所有功能都是它算的 | 502 网关错误，或页面能开但数据不来 |
| **SQLite** | 账本 | 一个叫 `db.sqlite` 的文件，存成绩、名单、访问码 | 页面能开但一条数据都没有 |
| **systemd** | 保姆 | 服务崩了自己拉起来，服务器重启自己启动 | 服务莫名停了、重启后要手动再开 |

一句话串起来：

```
浏览器 → 云安全组（放行 8090）→ Nginx:8090（验口令）→ Node:127.0.0.1:8091（干活）→ db.sqlite（存数据）
```

**为什么 Node 藏在 8091 不直接对外？**
因为 Node 自己不会验口令、不会限速、不会挡灌假成绩的脚本。让 Nginx 守前门，Node 只在里面干活，是这套结构存在的全部理由。8091 绑在 `127.0.0.1`，意味着**只有服务器自己能访问**，外面的人根本连不到那一层。

## 二、从零部署的八个步骤

### 第 1 步：确认系统够新

```bash
lsb_release -a          # 看是 Ubuntu 还是 CentOS
ldd --version | head -1 # 看 glibc 版本
```

**要求**：Ubuntu 20.04+ / Debian 11+ / Rocky 8+，glibc ≥ 2.28。

CentOS 7 不行 —— 它的 glibc 是 2.17，跑不了 Node 22 内置的 SQLite，会在启动时炸，而且报错完全看不出原因。

### 第 2 步：装 Node 22

```bash
node -v    # 先看有没有，要 v22.5 以上
```

没有或版本低：

```bash
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt-get install -y nodejs
node -v
```

**为什么必须 22.5+**：这个项目用的是 Node **内置**的 `node:sqlite` 模块，不是 npm 装的第三方包。内置模块是 22.5.0 才加进去的，22.0～22.4 没有。

### 第 3 步：装 Nginx 和口令工具

```bash
sudo apt-get update
sudo apt-get install -y nginx apache2-utils curl
```

`apache2-utils` 只为提供 `htpasswd` 命令（生成网页口令文件用）。CentOS 系对应包名是 `httpd-tools`。

### 第 4 步：把代码放上去

```bash
sudo mkdir -p /data/web/dazi-trainer
# 用 scp / 宝塔 / 解压包都行，把项目文件放进去
cd /data/web/dazi-trainer && ls server.js
```

看到 `server.js` 就对了。这套实例放在 `/data/web/dazi-trainer`；`setup.sh` 默认放 `/opt/typing-trainer`，两者都行，只要下面配置里路径对得上。

### 第 5 步：创建运行账号

```bash
sudo useradd --system --home /data/web/dazi-trainer --shell /usr/sbin/nologin typing
sudo chown -R typing:typing /data/web/dazi-trainer
```

**为什么不用 root 跑**：万一程序被攻破，攻击者拿到的只是 `typing` 这个不能登录的账号权限，不是整台机器。

### 第 6 步：注册成系统服务

新建 `/etc/systemd/system/typing-trainer.service`：

```ini
[Unit]
Description=Typing Trainer
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=typing
Group=typing
WorkingDirectory=/data/web/dazi-trainer

Environment=PORT=8091
Environment=BIND_HOST=127.0.0.1
Environment=PUBLIC_URL=http://43.142.117.18:8090
Environment=NO_OPEN=1
Environment=HIDE_CODES=1
Environment=ENABLE_SHUTDOWN=0
Environment=NODE_ENV=production

ExecStart=/usr/bin/node /data/web/dazi-trainer/server.js
Restart=always
RestartSec=3
LimitNOFILE=65535
KillSignal=SIGINT
TimeoutStopSec=20

StandardOutput=journal
StandardError=journal
SyslogIdentifier=typing-trainer

[Install]
WantedBy=multi-user.target
```

三个变量必须理解：

| 变量 | 值 | 作用 |
|---|---|---|
| `PORT` | 8091 | Node 自己用的端口，不对外 |
| `BIND_HOST` | 127.0.0.1 | **只监听本机**，公网连不到这一层 |
| `PUBLIC_URL` | `http://43.142.117.18:8090` | 学生端二维码按这个地址生成，填错二维码就废 |

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now typing-trainer
systemctl status typing-trainer     # 要看到 active (running)
```

### 第 7 步：配 Nginx（外面那扇门）

先造网页口令文件：

```bash
sudo htpasswd -bc /etc/nginx/typing.htpasswd typing '你的密码'
sudo chmod 644 /etc/nginx/typing.htpasswd    # ← 漏了这句就 500
```

新建 `/etc/nginx/conf.d/typing-trainer.conf`：

```nginx
upstream typing_backend {
    server 127.0.0.1:8091;
    keepalive 32;
}

limit_req_zone $binary_remote_addr zone=typing_write:10m rate=20r/s;

server {
    listen 8090;
    listen [::]:8090;
    server_name _;

    client_max_body_size 32m;

    auth_basic "打字练习系统";
    auth_basic_user_file /etc/nginx/typing.htpasswd;

    location = /api/shutdown { return 403; }

    location = /api/stream {
        proxy_pass http://typing_backend;
        proxy_http_version 1.1;
        proxy_set_header Connection '';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 24h;
    }

    location / {
        proxy_pass http://typing_backend;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_read_timeout 120s;
    }
}
```

三处不能改坏：

- `listen 8090` —— 对外端口
- `auth_basic_user_file` —— 口令文件路径
- `proxy_buffering off` 在 `/api/stream` 里 —— **不关的话大屏和进度墙永远不动**，因为实时推送被 Nginx 缓存住了

```bash
sudo nginx -t && sudo systemctl reload nginx
```

### 第 8 步：放行端口

两处都要开，缺一不可：

```bash
# 服务器本机防火墙（有 ufw 才需要）
sudo ufw allow 8090/tcp

# 腾讯云控制台 → 实例 → 安全组（CVM）或 防火墙（轻量）
# 入站规则加：TCP:8090，来源 0.0.0.0/0
```

验证（在**你自己电脑**上，不是服务器上）：

```powershell
Test-NetConnection 43.142.117.18 -Port 8090
```

`TcpTestSucceeded : True` 才算通。

## 三、怎么验证整套是好的

在服务器上依次跑，哪一步断就是哪一层的问题：

```bash
# 1. Node 活着吗
curl -s http://127.0.0.1:8091/api/ping | head -c 100

# 2. Nginx 转发对吗（期望 401，因为没带口令）
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8090/

# 3. 带口令能不能进（期望 200）
curl -s -u typing:你的密码 -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8090/

# 4. 外面能不能连（在你电脑上跑）
#    Test-NetConnection 43.142.117.18 -Port 8090

# 5. 浏览器
#    http://43.142.117.18:8090/  →  弹口令框  →  输 typing / 密码
```

| 返回 | 说明 |
|---|---|
| `1` 步失败 | Node 没起来或端口不对 → `journalctl -u typing-trainer -n 50` |
| `2` 步 404 | 请求没进这个 server 块 → 检查有没有别的站点抢了 `default_server` |
| `2` 步 500 | 口令文件读不到 → `chmod 644` + 看 `nginx error.log` |
| `2` 步 502 | Nginx 连不上 Node → 确认 `proxy_pass` 端口与 `PORT` 一致 |
| `4` 步 False | 云安全组 / ufw 没放行 |

## 四、这次实际踩过的六个坑

留着备查，下次换机器大概率还会遇到。

| 现象 | 真实原因 | 解决 |
|---|---|---|
| 浏览器打开是 nginx 欢迎页 / 404 | Ubuntu 自带的 `sites-enabled/default` 抢了 `default_server`，`server_name _;` 永远匹配不上 | `sudo rm -f /etc/nginx/sites-enabled/default` 后 reload |
| `curl 127.0.0.1/api/ping` 返回 nginx 的 404 网页 | 同上，请求压根没到 Node | 同上 |
| `http://IP:8090` 连不上，但服务明明在跑 | Node 绑的是 `127.0.0.1`，这是设计，不是故障 | 走 Nginx；真要直连才改 `BIND_HOST=0.0.0.0` |
| 输完口令后 500 Internal Server Error | `htpasswd` 文件权限 640，worker 进程（www-data）读不到 | `sudo chmod 644 /etc/nginx/typing.htpasswd` |
| `sudo sed ... > /etc/nginx/xxx` 报 Permission denied | `>` 重定向由**普通用户**执行，`sudo` 只管前面的命令 | 先写 `/tmp/` 再 `sudo install -m 644`，或 `\| sudo tee` |
| 日志里学生地址是 `10.0.0.8:8090` | 那是内网 IP，公网学生连不上 | 设 `PUBLIC_URL=http://公网IP:8090` 后重启服务 |

## 六、日常运维（复制即用）

```bash
# 看状态
systemctl status typing-trainer

# 看实时日志（排错第一入口）
journalctl -u typing-trainer -f

# 重启
sudo systemctl restart typing-trainer
sudo systemctl reload nginx

# 看端口归谁
sudo ss -lntp | grep -E ':(8090|8091)\s'

# 看 Nginx 报错（排 500/502 必看）
sudo tail -30 /var/log/nginx/error.log

# 看数据库大小
ls -lh /data/web/dazi-trainer/data/
```

**重启顺序**：改代码 → 重启 `typing-trainer`；改 Nginx 配置 → `nginx -t` 再 reload nginx。两者别混。

## 七、还没做但必须做的三件事

### 1. 改掉默认访问码

默认 `admin888` / `teacher888` 写在程序里，全网上搜得到。进教师端 → 设置里改，或直接查库：

```bash
sudo node -e "const{DatabaseSync}=require('node:sqlite');const d=new DatabaseSync('/data/web/dazi-trainer/data/db.sqlite');console.log(d.prepare('select * from meta').all())"
```

### 2. 配域名上 HTTPS

现在走 HTTP，学生姓名、成绩、口令全部明文经过公网。学校场景这块躲不过去。

有域名（比如 `dazi.example.com`，解析到 43.142.117.18）后：

```bash
sudo apt-get install -y certbot python3-certbot-nginx
sudo certbot --nginx -d dazi.example.com
```

然后把 Nginx 的 `listen 8090` 改回 `listen 80`（certbot 需要 80 做验证，HTTPS 走 443），并把 `PUBLIC_URL` 改成 `https://dazi.example.com`。学生以后输 `https://dazi.example.com/`，不用带端口。

### 3. 配每天自动备份

数据库就是**一个文件**，直接拷就行：

```bash
sudo crontab -e
# 加一行：每天 23:30 备份，保留 14 天
30 23 * * * cp /data/web/dazi-trainer/data/db.sqlite /data/backup/db-$(date +\%F).sqlite && find /data/backup -name 'db-*.sqlite' -mtime +14 -delete
```

记得先 `sudo mkdir -p /data/backup`。

## 八、以后升级怎么办

代码更新只改文件，不动数据库：

```bash
# 1. 先备份
sudo cp /data/web/dazi-trainer/data/db.sqlite /data/backup/db-manual-$(date +%F).sqlite

# 2. 覆盖代码（不要动 data/ 目录）
# 3. 重启
sudo systemctl restart typing-trainer

# 4. 验证
curl -s http://127.0.0.1:8091/api/ping | head -c 100
```

原则：**`data/` 目录永远不覆盖**。成绩全在里面。

## 九、出问题第一反应

不要猜。三条命令按顺序看：

```bash
systemctl status typing-trainer -l --no-pager   # 服务活没活
journalctl -u typing-trainer -n 50 --no-pager   # Node 报了什么
sudo tail -30 /var/log/nginx/error.log          # Nginx 报了什么
```

99% 的问题这两份日志里都写着。
