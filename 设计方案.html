01建设目标与设计取向

一句话：让全县每一个孩子都能在课堂上"看得见自己进步"，让每一位老师"看得见全班在哪儿卡住"。

打字（键盘输入）是信息科技课程的基础技能，但长期存在三个真问题：

🎯

练得没反馈

学生闷头打，不知道自己比别人快还是慢，也不知道错在哪个键，练 10 分钟和练 1 分钟感觉一样。

📊

教得没依据

老师只能看到"谁打得慢"，看不到"全班在哪个键上集体出错"，讲评靠感觉。

📈

管得没数据

县域层面要掌握各校开课情况，只能靠报表自报，缺少过程性、可比对的真实数据。

四条设计原则

原则具体做法为什么这样做
先准后快 准确率低于 85% 的成绩不计入排行榜，界面明确提示"再稳一点就能上榜"。 打字教学最大的坑是"瞎打求快"。规则层面就必须拦住这条路。
游戏不替代训练 游戏模式（落字）只承担"键位熟练度"，速度与准确率的正式成绩来自无干扰的计时练习。 游戏化的价值是兴趣和手速，不是评价。两者混在一起，数据就废了。
数据自动产生 学生正常练习，数据自动上报，不需要额外填表、打卡、截图。 任何需要老师额外操作的系统，两周后就会停用。
断网不废课 教师机单机起步即可用，学生端数据本地缓存，网络恢复后自动补传。 机房网络是常态风险，不能因为网断了这节课就上不了。

03登录身份：学校 → 班级 → 姓名

县级系统的身份必须能唯一确定一名学生，否则排行榜和学情分析全部失效。登录采用三段式，不做自由输入：

字段输入方式规则
学校下拉选择来自 data/schools.json，教师端可维护；默认内置本县学校名单模板
班级下拉选择随学校联动，如"三年级 1 班"；支持自定义新增（新学年直接加）
姓名文本输入2—10 个汉字；同班重名自动加序号后缀并提示，避免成绩串号
为什么不用账号密码 小学课堂没有时间做账号体系。用"学校+班级+姓名"作为唯一标识，一次登记就能开始练，不设密码、不建账号。

机房里一台电脑多人共用，所以登录状态只活在当前标签页里：关掉浏览器再打开，必须重新登记， 不会把上一位同学留在页面上；但按 F5 刷新不会掉登录，学生误触刷新不至于白练一局。 换人时点顶栏「换个同学」，或者直接关掉重开 —— 学校和班级会按这台电脑上次用的预选好， 姓名永远不预填，下一位同学只写自己的名字。

座位号防串号（可选）

机房常见问题是"张三用李四的机器登录，成绩记到李四头上"。系统提供可选开关：登录时可填机位号，教师端可按机位核对；同时同一身份在 3 分钟内从两台不同机器登录会在大屏标黄提示"身份重复"，老师一眼可见。

04五类练习模式设计

五种模式对应打字能力的五个层面：知道用哪根手指（键位）→ 手能跟上眼（反应）→ 能持续稳定输出（速度）→ 能在真实语料里保持准度（英文应用）→ 能用输入法把中文打对打快（中文应用）。

⌨️

① 键位闯关 教学引导

按提示逐个按键，屏幕实时高亮该用哪根手指。分 5 关推进，正确率不达标不放行。
定位：三年级起点课、新课导入。

🎮

② 落字游戏 游戏化

字母与单词从顶部下落，按对键击落得分，漏掉扣血。速度逐波加快，连击有额外奖励。
定位：热身、兴趣维持、手速训练。

⏱️

③ 速度练习 正式测评

金山打字通式界面：给一段文本，逐字符高亮、错误标红，实时显示 CPM / 准确率。可设 1/2/3/5 分钟。
定位：正式成绩来源、单元测评。

🚀

④ 单词冲刺 限时挑战

60 秒内尽可能多地打对英文单词，打错不前进。词库按学段分级。
定位：课堂竞赛、课前 5 分钟。

🈶

⑤ 中文跟打 输入法应用

用中文输入法照着短文打：上屏文字逐字比对，打错的字立刻变红、必须退格改正。按字/分钟计速。
定位：三—九年级日常练习，教师可导入本班文本。

⑤ 中文跟打：为什么不能像英文那样逐键判定

英文可以"按一个键判一个字符"，中文不行：学生敲的是拼音，屏幕上出现的是汉字，中间隔着输入法候选框，一次还可能上屏一个词。所以中文改用上屏结果比对：

打对字数 = 输入内容与目标文本的最长公共前缀
出错次数 = 出现"与原文不一致的字符"的次数（每次 +1）
有效速度 = 打对字数 ÷ 用时（分钟）→ 字/分钟
// 打错不前进：红字必须退格删掉，绿字才继续往后走
// 禁止粘贴（前端拦截）；服务端另设上限 250 字/分，超限不进榜

为什么单独一个榜：英文 120 CPM 很普通，中文 60 字/分已经算快，两者不是一个量纲。混在一张榜上会出现"练中文的人永远垫底"，教学上毫无意义。所以中文单独排「中文榜」，但同样计入个人总分（各模式最高分相加）。

⑤ 文本库：教师导入自己的文章

内置 4 篇中文短文够开课，但各校进度不同。超级管理员可在课堂管理 → 练习文本库里粘贴正文（或上传 .txt）导入，学生端「中文跟打」的文本下拉框里立刻可选；统一测评也能指定用某一篇。文本入库时自动压掉空白与多余换行、统计字数，20—3000 字，最多 100 篇。

① 键位闯关：五关递进与指法分工

关卡顺序遵循标准指法教学序列，每关要求打对 N 个键才算通过；打错不倒退，但会拉低准确率 —— 低于 85% 这一关不记成绩，得重打。

关卡键位范围内容与要求难度系数
第 1 关基准键 A S D F J K L ; + G H 手指归位。左手 A S D F、右手 J K L ;，食指负责 G H。打对 40 个键即通过；打错不倒退，只拉低准确率。0.80
第 2 关上排 Q W E R T Y U I O P 手指从基准位上抬击键后必须归位，界面会检测回位提示。打对 40 个键即通过；打错不倒退，只拉低准确率。0.85
第 3 关下排 Z X C V B N M 下排是错误率最高的一排，重点练 B（左手食指）与 N（右手食指）。打对 40 个键即通过；打错不倒退，只拉低准确率。0.90
第 4 关全字母混合 26 字母随机串，考察三排切换的流畅度。打对 60 个键即通过，标准同前。1.00
第 5 关数字与符号 1—0 , . ; ' - 数字排与常用标点，小学高年级与初中适用。打对 40 个键即通过；打错不倒退，只拉低准确率。1.10

屏幕上的虚拟键盘

键位闯关界面下方常驻一个虚拟键盘，三种颜色标记指法分区，目标键高亮闪烁并显示对应手指名称：

QWERT YUIOP
ASDFG HJKL;
ZXCVB NM

蓝色 = 左手　红色 = 右手　紫色 = 食指外扩（G H B N）

② 落字游戏：规则细节

要素设计
基础规则字母从顶部下落，按对应键击落。打对 +10 分，连击每 5 个加成分递增。
生命3 条命。字母落到底部 −1 命，按错键不扣命但连击清零。
难度曲线每 45 秒升一波，下落速度 +12%，同时下落的字母数上限 +1。用于观察"越打越乱"的临界点。
词库切换可选"纯字母"或"短单词"（如 cat / book / hand），后者需连续打对整词才消除。
结束条件生命归零，或达到设定时长（默认 90 秒）。
上报指标最终得分、最高连击、击落数、按错次数、平均反应时间（毫秒）。平均反应时间是这个模式最有价值的教学数据。
游戏模式的成绩不参与主榜 落字游戏的分数受随机生成影响，横向不可比。它只进"手速榜"（平均反应时间排名）与"连击榜"，避免污染速度榜的严肃性。

③ 速度练习：金山打字通式界面

这是唯一产生正式速度成绩的模式。界面自上而下分四区：

A. 参数区

时长（1 / 2 / 3 / 5 分钟）· 语料（键位串 / 英文单词 / 英文短文 / 数字与符号）· 是否显示虚拟键盘。语料决定难度系数，教师统一指定后全班可比。

B. 计时与指标区

大字显示 剩余时间、CPM、准确率、进度条。全部实时刷新，无延迟感。

C. 文本区

三行展示，当前字符带光标色块；已打对的字变绿，打错的字标红底，且必须打对才能前进（或按设置允许跳过并记为错误）。退回删除会记为一次修正，计入总击键。

D. 结束成绩单

时间到或文本打完即结算：CPM、WPM、准确率、正确/错误字符数、得分、本次在班级的排名变化。成绩单直接带"再来一次"与"上报"按钮。

④ 单词冲刺：60 秒

屏幕中央一次显示一个单词，打对即换下一个。词库三级：三年级 60 词 四—六年级 120 词 初中 180 词。倒计时结束统计"打对词数 / 平均每词耗时 / 准确率"。

05评分口径与排行榜规则

排行榜一旦不公平，整个系统的教学价值就崩了。规则必须满足三条：可比（不同练习能放在一起比）、防刷（重复练同一段不能无限加分）、可解释（能对家长和学校讲清楚）。

单次成绩得分

有效 CPM = 正确字符数 ÷ 实际用时（分钟）　// 英文/字符模式
有效 字/分 = 打对字数 ÷ 实际用时（分钟）　// 中文跟打
单次得分 = 有效速度 × 难度系数
// 准确率门槛：准确率 < 85% 的成绩标记为「未达标」，不计入排行榜
// 有效 CPM 已按正确字符计算，打错不涨分，天然抑制乱打
✅

为什么用有效 CPM 而不是总 CPM

总 CPM 把错字也算进速度，"狂敲乱打"能刷出高分。只算正确字符，乱打等于原地踏步。

⚖️

为什么乘难度系数

基准键的字母串当然比英文短文快。不校正难度，全校榜单会变成"谁练的关最简单谁第一"。

🚫

为什么设 85% 门槛

低于 85% 说明还没形成正确动作定型，此时的高速度是负资产。拦住它，就是教学导向。

学生总分（榜单排序依据）

个人总分 = Σ ( 各模式 历史最高单次得分 )　键位 + 速度 + 单词 + 中文
// 同一模式只取最高一次 → 重复刷同一段文本不会累加，防刷
// 落字游戏不进总分（随机性大），只进手速榜
// 键位闯关按「最高通过关卡」的得分计入，不再叠加各关

不同维度的榜单

榜单排序依据使用场景
总分榜 默认个人总分（各模式最高分之和）大屏主榜、班级评比、学期评优
速度榜速度练习的最高有效 CPM单元测评、速度达标检测
准确率榜速度练习的最高准确率（样本 ≥ 100 字符）纠正"求快不求准"，专门表扬稳的孩子
手速榜落字游戏的平均反应时间（毫秒，越小越好）游戏环节的竞赛榜
进步榜本周得分 − 上周得分关注后进生，这是最该被看见的一张榜
榜单口径必须全班统一 速度榜只有在同一语料、同一时长下才真正可比。系统在教师端提供"统一测评"开关：开启后全班被锁定为同一套参数，成绩单上会标注"统一测评"，榜单只取这类成绩。日常自由练习的成绩照常记录，但不进统一榜单。

06教师端与实时大屏

教师端：四个页签

页签内容
课堂总览 顶部四张指标卡（在线人数 / 平均 CPM / 平均准确率 / 达标人数）；中部实时进度墙（每人一张卡：姓名、当前模式、进度条、CPM、准确率、在线状态）；右侧实时动态（进入课堂、达成新纪录、连击、掉线）。
排行榜 五种榜单切换；可按全班 / 全年级 / 全校范围切换；每行显示名次、姓名、班级、总分、CPM、准确率、较上次变化。
学情分析 错键热力图、指法分区错误分布、模式参与度、速度分布直方图、班级横向对比、个人成长曲线（可下钻到单个学生）。
课堂管理 统一测评参数设置（速度练习 / 中文跟打）、学校班级维护、练习文本库（导入中文文本）、学生名单查看、清空本轮数据、导出 Excel/CSV、大屏入口二维码。
账号与权限 教师端凭访问码登录，分两档：超级管理员可导入/修改学校班级名单（支持 Excel/CSV，先预览再确认）；普通教师只用课堂功能、不能改名单。登录 12 小时内有效，关页即失效。学生端与大屏无需登录。

大屏看板：投屏专用

独立页面 /screen，设计目标是"最后一排也能看清"，因此：

  • 三栏布局：左榜单（前 10 名，名次变化有箭头动画）、中进度墙（按班级分组，每人一个方块，颜色表示进度）、右动态流（最新 12 条，自动滚动）。
  • 字号随屏宽缩放，1920×1080 与 1366×768 投影都能满屏显示，无横向滚动条。
  • 零操作按钮：投屏时鼠标不该出现在画面里。所有操作在教师端完成。
  • 冠军高亮：总分第一名卡片带金色边框与光效，动态流出现"新纪录"时全屏短暂提示。
  • 离线可见：学生掉线后卡片变灰但仍保留 20 分钟，老师能看到"谁掉出去了"而不是卡片突然消失。
技术上的实时性 采用 SSE（Server-Sent Events）长连接推送，服务端有变化立即广播，不是前端定时轮询。学生按下最后一个键到榜单刷新，延迟在 100 毫秒量级，学生能真切感受到"我上榜了"的即时反馈。

关键的一点是只推变化的那一行：学生进课堂、交成绩、改为在线状态，服务端都只发自己这一条（约 0.4—1.3 KB）， 不再把整份排行榜和整张在线列表推给每台机器。名次由学生端、教师端、大屏三端用同一份合并逻辑就地重算。 这样一来，1 个班用和 5,000 人同时用，单次推送量都一样， 不会出现"人一多、大屏就卡成幻灯片"的情况。

06+数据放在哪：SQLite 而不是 JSON

一台服务器扛全县学生，第一件事是把"每次提交都读写一整个 JSON 文件"换掉 —— 那个做法在几百人以下没问题，上千人就会互相覆盖、越写越慢。

方案能不能用结论
SQLite（现在用的）能。单文件数据库，Node 22 内置驱动，零安装选它。写入 0.3 毫秒一条，30 万条成绩冷启动 0.7 秒，看板查询 46 毫秒；支持热备份与断电恢复（WAL）。
MySQL / PostgreSQL能，但要装服务、配账号只有当"多个校区各开一套、再集中汇总到县里"时才值得上，那时才有并发写多库的需求。
纯 JSON 文件几千人就开始吃力每次提交全量序列化，多台机器同时写会互相覆盖。已全部迁移掉。

表设计是"明细只追加 + 写入时顺便算好汇总"：交一次成绩，一个事务里写明细记录、更新这个人的汇总行、累加错键统计 —— 看板永远只读汇总，不用回头扫全部明细。

07错键热力：把打字数据变成教学依据

这是本系统对教研最有价值的部分，也是普通打字软件没有的。

系统记录每一个击键的目标字符与实际字符，在教师端聚合成整班/整校的错键分布，用虚拟键盘热力图呈现：颜色越红表示该键错误率越高。老师投屏后可以直接说：

"全班在 B 和 N 这两个键上错了 37 次，都是食指该管的位置 —— 现在我们专门练 20 个 B 和 N。"

分析维度回答的教学问题
错键热力图全班在哪些键上集体出错？是某一排还是某个手指？
左右手错误比是普遍问题，还是个别学生左手不熟？（左撇子的分布也能看出）
混淆对 Top 10最常见的混淆是"目标 B 打成 V"这类邻键误触，还是"目标 M 打成 N"这类手指错位？前者是定位问题，后者是分工问题，训练方法完全不同。
错误类型分布误触邻键 / 手指错位 / 大小写 / 漏键 / 多余击键，五类占比。
速度—准确率象限图把全班画在"快而不准 / 又快又准 / 慢而准 / 待提升"四个象限，分层布置任务。
个人成长曲线某个学生 5 次练习的 CPM 与准确率双线走势，用于个别辅导与家校沟通。

技术选型

层面选择理由
服务端Node.js 内置模块，零第三方依赖机房电脑不需要联网装包，拷过去双击就能跑，也不会因为 npm 源被墙而装不上。
数据库SQLite（Node 22 内置 node:sqlite） 仍然不用装任何数据库服务，拷过去双击就能跑。成绩只追加一行，提交耗时 1~2 毫秒， 与历史数据多少无关（旧版 JSON 文件在 30 万条时要 4 秒多，一个班交卷就卡住服务）。 另设 person 汇总表与错键聚合表，榜单和学情直接读汇总，不必每次扫全表。
什么时候才需要 MySQL：一台机器上跑多份服务、或要跨机共享同一份数据时。 单机单进程的集中部署，SQLite 完全扛得住几千人。
实时通信SSE比 WebSocket 简单（纯 HTTP），断线自动重连，单向推送正合适。
前端原生 HTML/CSS/JS，无框架机房老机器、旧版浏览器也能跑；不依赖 CDN，断网可用。
部署教师机局域网，默认端口 8090一台机器开局域网广播，学生扫码即入；不涉及数据出校，符合学生信息保护要求。

09课堂使用建议与部署

部署（教师机，5 分钟）

  1. 把 打字练习系统-联网版 文件夹拷到教师机任意位置。
  2. 双击 start.bat（需已装 Node.js）。控制台会打印三个地址：教师端、大屏、学生端。
  3. 教师端浏览器打开 http://localhost:8090/teacher；投影机打开 /screen。
  4. 学生端地址形如 http://192.168.x.x:8090/，大屏会显示二维码，学生扫码直接进。
机房网络的两个坑 ① 学生机需要和教师机在同一网段；② 教师机防火墙要放行端口（启动脚本会尝试自动添加规则，无管理员权限时需手动放行）。这两条写在启动时的控制台提示里。
